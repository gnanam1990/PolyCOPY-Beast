# v3.2 CLOB V2 Migration — Phase 2: Config V2 scaffolding + Phase 1 follow-ups

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add V2 configuration surfaces (Relayer, Collateral, Builder, category caps, fee threshold) and fix the three Phase 1 review follow-ups, without changing runtime behavior or deleting any V1 code.

**Architecture:** Purely additive. New `RelayerConfig`, `CollateralConfig`, `BuilderConfig` structs on `AppConfig` are all wrapped in `Option<>` — if unset they're `None` and V1 code paths are unaffected. Env parsing prefers bare V2 names (`BUILDER_CODE`, `RELAYER_URL`, …) but falls back to `POLYBOT_*` prefix where analogous. No env var is renamed; none is removed. The three Phase 1 follow-ups are implemented as small, reviewable commits.

**Tech Stack:** Rust 2021, `serde`, `rusqlite` 0.31, `rust_decimal`, `toml`, `dotenvy`.

- Removing `#![allow(dead_code)]` from `main.rs` — Phase 3 (likely cascades)
- Any V2 SDK work — Phase 4 (blocked on SDK identity)
- Order builder changes — Phase 4
- Writer paths that populate the new V2 trade columns — Phase 4+ (Phase 2 only fixes the INSERT column list; zero-valued V2 fields continue to write zero-valued)
