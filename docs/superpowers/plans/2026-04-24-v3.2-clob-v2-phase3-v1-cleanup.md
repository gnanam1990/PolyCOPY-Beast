# v3.2 CLOB V2 Migration — Phase 3: V1 RPC/gas cleanup + env rename

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Delete V1 RPC/gas infrastructure (unused in V2's gasless flow) and rename `POLYBOT_PRIVATE_KEY` → `POLYMARKET_PRIVATE_KEY` with an alias window, without breaking V1 live-trading behavior that still depends on the Polymarket CLOB SDK's own RPC handling.

**Architecture:** V2 order submission goes through Polymarket's relayer (Phase 2 scaffolded the config); the bot no longer holds POL or signs on-chain transactions itself. So every piece of RPC plumbing in `polybot-core` — the `rpc_pool` module, the `rpc_endpoints` config field, the `POLYGON_RPC_URL` env var, the `validate_rpc_connectivity` preflight, the `_rpc_pool` unused binding — is dead weight and comes out. The private key remains a requirement (for order EIP-712 signing), but is renamed to `POLYMARKET_PRIVATE_KEY` per PRD §6; `POLYBOT_PRIVATE_KEY` continues to work as a deprecation alias with a warning.

**Tech Stack:** Rust 2021, `serde`, `tracing`, existing test infrastructure including `serial_test` (added in Phase 2 follow-up).

**Out-of-scope for this phase:**
- Deleting CLOB credential persistence (`clob_credentials.json` write/read paths in `execution/clob_client.rs`) — Phase 4 owns that (depends on V2 SDK swap)
- Removing `#![allow(dead_code)]` from `main.rs` — deferred; Phases 4/5 will delete whole subsystems (RpcPool code shells, V1 order builder), and the dead-code sweep makes more sense after that settles
- Any V2 SDK work — Phase 4
- Relayer client implementation — Phase 5
- Any runtime behavior change in simulation mode — simulation must still start cleanly after Phase 3
- Removing the `clob_client::ClobClient::from_env` code paths that currently read `POLYBOT_PRIVATE_KEY` — this plan renames the read, it doesn't delete the function

**Verification gates:** `cargo test --workspace` + `cargo clippy --workspace -- -D warnings` green after every task. `POLYMARKET_PRIVATE_KEY=0x… cargo run --release -p polybot-core -- --setup-check` starts in simulation mode. `POLYBOT_PRIVATE_KEY=0x… cargo run ...` likewise works (with a deprecation warning).
